DevStepsHuman Guide

わからない時代から、
決めれば進める時代へ

AI時代の開発は、「人間が一つずつ作る」から「人間が決め、AIが進み、未決定だけを共同で決める」へ変わる。

1. なぜDevStepsなのか

ウォーターフォールは、要求から設計、実装、テスト、リリースまでを順序立てて進める。最初に十分なことが決まっているなら合理的だ。

一方、現実には最初からすべてはわからない。そこでアジャイルは、小さく作り、試し、結果から次を決める方法を発達させた。

AIはこの関係を変える。
宣言された目的・制約・設計があれば、AIはDesign → Code → Test → Build → Deployを連続して展開できる。だから新しいボトルネックは「作業」より「決定」になる。

2. テーゼとアンチテーゼ

テーゼ：決まっているなら、一気に進めればよい。AIによって工程の自動展開が可能になる。

アンチテーゼ：それでも全部は最初に決められない。UI、データソース、品質、方針など、実行して初めて現れる未知もある。

止揚：全体はWaterfall的に進め、未決定部分だけAgile的に対話する。

3. DevStepsの基本ループ

01 DECLARE — HumanがGoal・制約・既知の決定を宣言
↓
02 EXPAND — AIが宣言された範囲を設計へ展開
↓
03 EXECUTE — AI / WF / AW / UiPathが実行
↓
04 DETECT — AIが未決定・不足Input・Bottleneckを検出
↓
05 DEMAND — AIが必要な一点だけ質問
↓
06 DECIDE — Human + AIで決定
↓
07 UPDATE / CONTINUE — YAML / Graphを更新して再開
↓
08 GATE — 条件を満たせばPASS、未達ならBLOCK

4. 誰が何をするのか

Human

決定者
Goal、制約、価値判断、未決定事項、Gate承認を決める。

AI

計画・実行者
宣言された範囲を設計・実装・検証し、未決定だけDemandする。

AW

オーケストレータ
Repo、Graph、Agent、WFを接続して進行させる。

UiPath

GUI実行者
APIやCLIで扱えないBrowser / Desktop / GUIを担当する。

WF

決定論的実行者
Test / Build / Deploy / 定期処理を再現可能に実行する。

GitHub

記録媒体
設計・判断・実装・自動化・成果をSource of Recordとして保持する。

5. AIはどこで止まるのか

AIは「できないから止まる」のではなく、決めてはいけない場所に到達したら止まる。

  • Goalが未定義
  • 必須制約が未定義
  • Product / UX / Businessの価値判断が未決定
  • Policy変更が必要
  • 実行Inputが不足
  • Bottleneck解消にHuman判断が必要
  • Gateの承認が必要

ただし、停止点より前の独立した宣言済み範囲は可能な限り進める。

6. Demand / Decision / Gate

Demandは「次に人間から必要な入力」。Decisionは、そのDemandに対する決定。Gateは、次の工程へ進んでよいかを判定する関門。

demand:
  id: demand-test-method
  from: test-gate
  target: decision-test
  type: bottleneck
  question: "テスト方法を決めてください"
  options:
    - github-actions
    - local
    - both

AIはOptionを最大3つまで整理できる。しかし、人間の価値判断を勝手に確定しない。

7. Graphは進捗表ではなく設計そのもの

DevStepsではNodeとEdgeがプロセスの状態を表す。

Node = Goal / Decision / Phase / Task / Gate / Automation / Demand

Edge = demand / answer / result / pass / block / depends_on

Owner = 誰が担当するか

Scope = どこまで実行してよいか

Gate = 次工程へ進む条件

Graphは単なる可視化ではない。Block同士がDemand・Answer・Resultを交換することで設計が前進する。

8. YAMLが正本

YAMLはSingle Source of Truth。YAMLのBlockをReact Nodeへ1:1、YAMLのEdgeをReact Edgeへ1:1で変換する。GUI専用の別データモデルは作らない。

Goal
  ↓ demand
Decision
  ↓ answer
Phase
  ↓ demand
Task
  ↓ result
Gate
  ↓ pass
Next Phase

9. 開発の中心が変わる

AIによってコードを書く価値がなくなるのではない。開発の中心が、コードそのものから「何が決まっていて、何が決まっていないか」へ移る。

したがって進捗も、実装量だけでなくDecision、Undecided、Blocked、Bottleneckで見る。

Progress   72%
Decisions   8
Undecided   2
Blocked     1
Bottlenecks 1

10. 一言でいうと

AIは勝手に決めない。

しかし、決まったことは遠慮なく進める。

人間はすべてを逐次指示する必要がない。AIは未決定事項を発見し、必要なときだけHumanへDemandを返す。回答された瞬間に、また先へ進む。
